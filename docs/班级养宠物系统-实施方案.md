# 班级养宠物系统 — 实施方案

## Context

老师在课堂里希望用游戏化方式管理学生行为：每个学生认领一只虚拟宠物，老师对学生的行为（积极/消极）一键加减分，分数会自动换算成宠物的经验、心情、饥饿等属性变化，长期表现好的学生宠物会升级。这把"打分"这件抽象的事转化成学生看得见、有情感连接的反馈，提高激励效果。

项目同时承担**全栈能力训练**目标：前端 Vue 3 + 后端 Python FastAPI + 数据库 MySQL，覆盖完整 Web 应用全链路。

**MVP 目标**：低限闭环可用——老师能注册登录、建班级、加学生、给学生加减分、看到宠物属性随之变化即可。不做：成长进化、排行榜大屏、家长端、学生端、多端复用。

## 数据模型（5 张表）

```
teachers (老师)
  id PK, username UNIQUE, password_hash, display_name, created_at

classes (班级)
  id PK, teacher_id FK→teachers, name, grade, created_at

students (学生)
  id PK, class_id FK→classes, name, student_no, created_at

pets (宠物，与学生 1:1)
  id PK, student_id FK→students UNIQUE, name, species,
  level (默认 1), exp (默认 0),
  hunger (0-100, 默认 60), mood (0-100, 默认 80),
  last_updated_at, created_at

behaviors (行为记录)
  id PK, student_id FK→students, teacher_id FK→teachers,
  score (-10 ~ +10), category (积极/消极/学习/纪律),
  reason VARCHAR(200), created_at
```

**关键关系**：
- 一个老师 → 多个班级
- 一个班级 → 多个学生
- 学生创建时自动生成一只宠物（默认名字 + 默认属性）
- 每条行为记录都会通过 `pet_service` 计算并写回宠物属性

## 核心业务规则：行为分 → 宠物属性换算

写在 `class-pet-backend/app/services/pet_service.py`，在 `POST /behaviors` 接口里同事务调用。

**加分（score > 0，奖励行为）**：
- `exp += score * 10`
- `mood = min(100, mood + score * 5)`
- `hunger = min(100, hunger + score * 3)`（加分意味着投喂/陪伴）

**减分（score < 0，惩罚行为）**：
- `mood = max(0, mood + score * 5)`
- `hunger = max(0, hunger + score * 2)`
- 不扣经验

**升级规则**：
- 升级阈值：`exp_threshold = level * 100`
- 当 `exp >= exp_threshold`：`level += 1`，`exp -= exp_threshold`
- 可循环升级（一次行为可能跳多级）

**衰减规则（懒计算）**：
- 每次读取宠物时，根据 `now - last_updated_at` 计算流逝小时数
- 每 24 小时 hunger 和 mood 各 -5（封顶不低于 0）
- 写回 `last_updated_at = now`
- 优点：免去定时任务，部署简单

**派生状态（仅前端展示用，不入库）**：
- `健康`: hunger > 30 && mood > 30
- `饥饿`: hunger ≤ 30
- `难过`: mood ≤ 30
- `虚弱`: hunger ≤ 10 ‖ mood ≤ 10

## API 设计（REST，前缀 `/api/v1`）

| Method | Path | 说明 |
|--------|------|------|
| POST | `/auth/register` | 老师注册（用户名/密码/显示名） |
| POST | `/auth/login` | 登录，返回 JWT |
| GET | `/auth/me` | 当前老师信息 |
| GET | `/classes` | 我的班级列表 |
| POST | `/classes` | 创建班级 |
| DELETE | `/classes/{id}` | 删除班级（连带学生/宠物/行为） |
| GET | `/classes/{id}/students` | 班级内学生列表（含宠物简要属性） |
| POST | `/classes/{id}/students` | 添加单个学生（自动建宠物） |
| POST | `/classes/{id}/students/batch` | 批量导入学生（接收姓名列表） |
| DELETE | `/students/{id}` | 删除学生 |
| GET | `/students/{id}` | 学生详情（含宠物完整属性） |
| GET | `/pets/{id}` | 宠物详情（先跑衰减再返回） |
| PATCH | `/pets/{id}` | 改宠物名 |
| GET | `/students/{id}/behaviors` | 该学生的行为历史 |
| POST | `/behaviors` | 记录行为，事务内同步更新宠物属性 |

权限：除 `/auth/*` 外所有接口需 JWT，资源访问校验 `teacher_id` 所有权。

## 前端页面与交互

### LoginView
- 登录 / 注册 Tab 切换
- 登录成功后存 token 到 Pinia + localStorage，跳 `/classes`

### ClassesView
- Element Plus 卡片网格列出"我的班级"
- 顶部"新建班级"按钮 → 弹窗输入年级 + 班名

### ClassDetailView（核心使用场景）
- 学生表格：姓名 / 学号 / 宠物名 / 等级 / 心情条 / 饥饿条 / 状态标签
- 每行右侧"+ 加分""- 减分"按钮（弹出 BehaviorQuickPanel）
- 顶部"添加学生"按钮（单条 + 文本框批量粘贴）
- 表格行点击 → 跳学生详情

### StudentDetailView
- 顶部 PetCard：等级/经验进度条/心情条/饥饿条/派生状态徽章
- 中部 BehaviorQuickPanel：预设按钮（积极发言+3、迟到-2、作业优秀+5、违纪-3）+ 自定义输入
- 下方行为时间线：最近 50 条按时间倒序

### BehaviorQuickPanel（组件）
- 预设按钮内置在前端常量里，避免后端字典维护开销
- 提交后乐观更新本地宠物状态，并刷新行为列表

## 实施步骤

### Phase 0：脚手架（半天）
1. 在 `teacher_app/` 下创建 `class-pet-backend/` `class-pet-frontend/` 两个目录，**各自 `git init`**
2. 各自创建 `.gitignore` `README.md`
3. 后端：`cd class-pet-backend && python -m venv .venv`、`pip install fastapi uvicorn sqlalchemy alembic pymysql python-jose passlib[bcrypt] python-multipart pydantic-settings`、生成 `requirements.txt`
4. 前端：在 `teacher_app/` 下执行 `npm create vite@latest class-pet-frontend -- --template vue-ts`、`cd class-pet-frontend && npm i element-plus pinia vue-router axios`
5. 创建 MySQL 数据库 `class_pet`，在后端 `.env` 里配置连接串

### Phase 1：后端基础（半天）
1. 实现 `core/config.py`、`db/session.py`、`db/base.py`、`main.py`
2. `alembic init alembic` 并配置（读 `.env` 里的 DATABASE_URL）
3. 写第一个健康检查接口 `GET /api/v1/ping`，确认服务起得来

### Phase 2：认证（半天）
1. `models/teacher.py` + `schemas/auth.py`
2. `core/security.py`（bcrypt 哈希 + JWT 签发/校验）
3. `core/deps.py` 的 `get_current_teacher` 依赖
4. `api/v1/auth.py` 三个接口
5. Alembic 生成第一个 migration 并 upgrade

### Phase 3：班级 + 学生（1 天）
1. 表模型 + Pydantic schema
2. `classes.py` `students.py` 路由（含权限校验：只能操作自己班级）
3. **学生创建 → 自动建宠物**（同事务）
4. 批量导入：粘贴一段每行一个姓名的文本

### Phase 4：宠物 + 行为换算（1 天）
1. `models/pet.py` `models/behavior.py`
2. `services/pet_service.py`：`apply_behavior()`、`apply_decay()`、`level_up()`

4. **POST /behaviors 是核心接口**：在一个事务里写行为记录 + 跑衰减 + 应用加减分 + 处理升级

### Phase 5：前端整合（1.5 天）
1. axios 实例 + 拦截器（注入 token、401 重定向登录）

## 验收方式

启动三件套：
```bash
# 1. MySQL 已起（本地或 Docker）
# 2. 后端
cd class-pet-backend && uvicorn app.main:app --reload --port 8000
# 3. 前端
cd class-pet-frontend && npm run dev
```

走一遍业务流：

1. 打开 `http://localhost:5173`，注册老师 `teacher01` / `123456`
2. 登录后进入班级页，新建班级"五年级三班"
3. 进班级，批量粘贴 5 个学生姓名导入
4. 检查每个学生默认有一只宠物（等级 1，hunger=60，mood=80）
5. 给"张三"点 `+5 学习积极` → 观察 mood、hunger、exp 上涨
6. 连续给 `+10 +10 +10` → 验证升级（level 2，exp 归零进入下一级）
7. 给"李四"点 `-5 违纪` → mood、hunger 下降，exp 不变
8. 给"王五"点到 hunger ≤ 30 → 状态标签变"饥饿"
9. 退出账号重新登录，所有数据保留
10. 打开 `http://localhost:8000/docs`，逐个接口在 Swagger UI 上手动 smoke 测试
