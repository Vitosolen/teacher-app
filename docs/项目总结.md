## 1. 一句话项目

老师端 Web 应用：把"打分"游戏化——每个学生认领一只虚拟宠物，老师对学生行为加减分驱动宠物属性，积分可在商城兑换房子/家具/衣服/食物，宠物住进房子里展现日常活动；同时支持作业管理、成绩登记、单词听写、随机点名等课堂工具。

**目录**：
- `class-pet-backend/` — Python FastAPI 后端
- `class-pet-frontend/` — Vue 3 前端
- `docs/` — 文档

## 2. 技术栈

| 层 | 选型 |

## 3. 已实现功能（按迭代分组）

### 迭代 1 — MVP（核心闭环）
- 老师注册 / 登录（JWT，有效期 7 天）
- 班级 CRUD
- 学生 CRUD（含批量粘贴导入）
- 宠物属性：等级 / 经验 / 心情 / 饥饿 / 派生状态（健康/饥饿/难过/虚弱）
- 行为打分 → 宠物属性自动换算 + 升级 + 懒衰减

### 迭代 2 — 课堂工具与游戏化深化
- **班级/学生编辑**（PATCH 接口）
- **科目管理**（按老师隔离）
- **作业管理**：选班级+科目建作业 → 自动绑定全班 records → 批改打分点评
- **积分规则字典化**：取代硬编码 9 个预设按钮，老师可自定义；注册时自动复制默认规则
- **学生积分余额**（students.points）：加分累加，扣分不扣，购物扣减
- **宠物商城**：12 件预置商品（食品/衣服/玩具）→ 兑换 → 装备/食用/玩耍
- **随机点名**：转盘动画

### 单词听写
- 词库分组（按老师隔离，含 `lang` 字段决定 TTS 语言）
- 单词 CRUD + 批量粘贴 + Excel 导入（前端 SheetJS 解析）
- 听写播放器：抽取数量 / 朗读遍数 / 词间间隔 / 语速 / 是否打乱；播完展示答案让学生对

### 宠物世界扩展
- **新增 8 件商品**：3 房子 + 5 家具
- **装备规则**：衣服/房子互斥（同时装备 1 件，自动替换）；家具不互斥（多件并存）
- **可视化场景** `PetSceneView.vue`：CSS 模拟房间内部空间（屋顶+墙壁+地板）；家具按 emoji 名字摆固定位置；宠物 4 种活动状态自动循环（站立/睡觉/吃饭/玩耍）；穿戴衣服叠加在宠物身上

### 领养系统
- 学生创建时不再自动建宠物
- 6 种宠物 × 4 阶段成长 emoji（小龙/小猫/小狗/小兔/熊猫/狐狸 × 蛋→幼→少→成）
- 等级 → 阶段映射：1 级蛋 / 2 级幼 / 3-4 级少 / 5+ 成

### 打分增删改
- score 范围放宽：±10 → **±100**
- `PATCH /behaviors/{id}` 改 reason/category（不允许改 score）
- `DELETE /behaviors/{id}` 删除时若原 score>0 回滚 student.points

### 成绩登记 + 作业订正
- `homeworks.type` 字段：`homework`（作业）/ `exam`（成绩）
- 作业批改时分数 < 90 自动 `needs_correction=true`；老师可标记"已订正"
- 重新批改自动重置已订正状态
- 考试不触发订正，仅记分

## 4. 数据模型（13 张表）

### 业务表

```
teachers          老师账号 + JWT 主体
classes           班级（按 teacher 隔离）
students          学生 + points（可消费积分余额）
pets              宠物（与 student 1:1，species 决定 emoji 图组）
behaviors         行为记录（含可空 score_rule_id）
subjects          科目（按 teacher 隔离）
score_rules       积分规则（按 teacher 隔离，注册时复制默认 9 条）
homeworks         作业/考试（type 区分）
homework_records  学生作业记录（needs_correction / corrected / corrected_at）
shop_items        商品池（系统全局，5 类 20 件）
pet_owned_items   宠物拥有物品（equipped 标记装备状态）
word_groups       单词词库（lang 字段决定 TTS 语言）
words             单词条目
```

### 关键关系

- 老师 → 班级 → 学生 → 宠物 → 拥有物品
- 老师 → 科目，老师 → 积分规则
- 班级 + 科目 → 作业 → 学生作业记录
- 老师 → 词库 → 单词

### 关键字段约束

- 学生创建时**不**自动建宠物，需通过 `POST /students/{id}/adopt-pet` 领养
- 装备互斥：衣服 / 房子（同类自动卸下其他），家具不互斥
- 行为 score：±100；积分规则 score：±100
- 订正阈值：作业批改分数 `< 90` 自动 needs_correction（`CORRECTION_THRESHOLD`）

## 6. 核心业务规则（再迭代时不可破坏）

### 行为打分 → 宠物属性

```
score > 0:
  pet.exp += score * 10
  pet.mood += score * 5  (封顶 100)
  pet.hunger += score * 3 (封顶 100)
  student.points += score   ← 同步累加余额
score < 0:
  pet.mood += score * 5   (保底 0)
  pet.hunger += score * 2 (保底 0)
  不扣 exp，不扣 student.points
```

### 升级
- 阈值：`level * 100`
- 满足时 level++，exp -= 阈值；可循环升级

### 懒衰减
- 读取宠物时按 `now - last_updated_at` 算流逝小时数
- 每 24h 心情 -5、饥饿 -5（保底 0）

### 派生状态（前端展示，不入库）
- `hunger ≤ 10 || mood ≤ 10`：虚弱
- `hunger ≤ 30`：饥饿
- `mood ≤ 30`：难过
- 否则：健康

### 物品装备规则
- **衣服**：互斥（同时只能 1 件）
- **房子**：互斥（同时只能 1 个）
- **家具**：不互斥（多件并存装饰房间）
- **食品 / 玩具**：不可 `equip`，必须 `consume`

### 作业订正
- 仅作业（type=homework）：分数 `< 90` 自动 `needs_correction=true`
- 重新批改重置 `corrected=false`（学生需再次订正）
- 考试（type=exam）不触发订正

### 行为删除回滚
- 删除 score>0 的 behavior：`student.points -= score`（保底 0）
- 不回滚宠物属性（衰减/升级已发生不可逆）

## 10. 已知坑位（避免重新踩）

### 坑 1：alembic + SQLite + Windows 不真正 commit

**症状**：`alembic upgrade head` 输出"Running upgrade ..."无报错，但 db 中表/列没真正创建，`alembic_version` 也不写入。

**应对**：每次新增 migration 后用直连 sqlite3 手动 commit + 手动改 `alembic_version`：

```python
import sqlite3
con = sqlite3.connect('class_pet.db')
con.execute("ALTER TABLE ... ADD COLUMN ...")
con.execute("UPDATE alembic_version SET version_num='<new_revision>'")
con.commit()
```

**为什么**：根因未深究，疑似 alembic env.py 里 `with context.begin_transaction()` 在 SQLite "non-transactional DDL" 模式下没正确 commit。MySQL 不会有这个问题。

### 坑 2：bcrypt 5.x 与 passlib 1.7.4 不兼容

requirements 已经 `bcrypt<5` 锁住，不要升级。

### 坑 3：Windows 端口僵尸

`taskkill` 之后 `netstat` 还显示 LISTENING + PID 已失效。换端口（8001/8002）绕过；或用 PowerShell `Stop-Process -Force`。

### 坑 4：uvicorn `--reload` 有时不重载

热重载偶发失效（特别是新增文件、删除 `__pycache__`），改了模型/接口后保险起见手动 kill 重启。

### 坑 5：Vite dev server 端口冲突自动 +1

5173 占用时变 5174。E2E 脚本里的 `BASE` 写死 5174，记得检查实际端口。

### 坑 6：Pydantic from_attributes 缺字段会报错

`OwnedItemOut.item: ShopItemOut` 在 `model_validate(rec)` 时找不到 `rec.item` 属性会 422。解决：字段设默认值 `item: ShopItemOut | None = None`，业务层手动赋值。

## 11. 添加新功能的标准流程

下次新需求按这个套路最快：

### 后端
1. **建 Model** in `app/models/<name>.py` —— `class Foo(Base): __tablename__ = "foos"`
2. **注册到 alembic env**：`alembic/env.py` 末尾 import
3. **生成迁移**：`alembic revision --autogenerate -m "add foo"`
4. **应用迁移** + 用 sqlite3 验证表 + 手动 stamp `alembic_version`（见坑 1）
5. **建 Pydantic schemas** in `app/schemas/<name>.py` —— `FooCreate / FooUpdate / FooOut`
6. **建路由模块** in `app/api/v1/<name>.py` —— 用 `_ensure_<resource>_owned()` 封装权限校验
7. **挂到聚合 router**：`app/api/v1/__init__.py` 加 `from . import <name>` + `api_router.include_router(<name>.router)`
8. 重启 uvicorn → curl /openapi.json 确认路由出现

### 前端
1. **加类型** in `src/types/domain.ts`
2. **加 API 客户端** in `src/api/<name>.ts`
3. **加视图** in `src/views/<Name>View.vue` + 路由 in `src/router/index.ts`
4. **加菜单** in `src/App.vue`（如果需要顶栏入口）
5. **vue-tsc** 类型检查 + curl Vite 编译每个新文件

### 验证
1. 写 `e2e_<name>.py`：`from httpx import Client` + `BASE = "http://127.0.0.1:5174/api/v1"` + 验证业务流
2. 跑通后任务才算完
