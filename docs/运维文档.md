# 班级养宠物系统 · 运维文档

> 给"运维 / 部署 / 排障"角色看的。讲清楚：怎么从 0 部署到能跑、怎么日常启停、出问题怎么修。

> 业务使用流程见 `docs/操作文档.md`。

## 1. 系统组成

```
浏览器
   │  http://<host>:5173
   ▼
Vite dev server (前端)              ──┐
   │  /api → http://127.0.0.1:8000   │
   ▼                                  │ 同源代理（避免 CORS）
Uvicorn (后端 FastAPI)               ──┘
   │
   ▼
SQLite 文件 class_pet.db
```

- 前端 Vite dev server（5173）通过 `/api` 反向代理后端，**前后端必须同时运行**，缺一不可
- 后端默认监听 8000，前端默认监听 5173（被占自动 +1）
- 数据库默认是后端目录下的 `class_pet.db` 文件（SQLite，单文件）


> ```
> 应看到 13 张业务表 + `alembic_version`。如果只看到几张表，按 §8.4 处置。

## 4. 一键启动脚本

把下面两段保存为项目根目录下的 `start.bat`（Windows 双击启动），就不用每次敲命令：

```bat
@echo off
REM 启动后端（新窗口）
start "class-pet-backend" cmd /k "cd /d %~dp0class-pet-backend && .venv\Scripts\activate.bat && uvicorn app.main:app --reload --host 127.0.0.1 --port 8000"

REM 启动前端（新窗口）
start "class-pet-frontend" cmd /k "cd /d %~dp0class-pet-frontend && npm run dev"

REM 等 5 秒后打开浏览器
timeout /t 5 /nobreak > nul
start http://127.0.0.1:5173

echo 启动完成。后端在 :8000，前端在 :5173。关闭两个 cmd 窗口即可停止服务。
```

PowerShell 版本 `start.ps1`：

```powershell
$root = $PSScriptRoot

Start-Process powershell -ArgumentList @(
  "-NoExit", "-Command",
  "cd '$root\class-pet-backend'; .\.venv\Scripts\Activate.ps1; uvicorn app.main:app --reload --host 127.0.0.1 --port 8000"
)
Start-Process powershell -ArgumentList @(
  "-NoExit", "-Command",
  "cd '$root\class-pet-frontend'; npm run dev"
)

Start-Sleep -Seconds 5
Start-Process "http://127.0.0.1:5173"
```

## 5. 端口与网络

### 5.1 默认端口

| 端口 | 服务 | 协议 |
|---|---|---|
| 8000 | 后端 FastAPI | HTTP |
| 5173 | 前端 Vite dev server | HTTP |
| 5174、5175... | Vite 自动顺延（5173 被占时） | HTTP |

### 5.2 让其他设备访问（局域网部署给学生大屏看等）

默认 host 绑 `127.0.0.1`，只本机能访问。要开放给同一局域网（例如教室里的投影仪）：

**1. 改前端 `vite.config.ts`**
```ts
server: {
  host: '0.0.0.0',   // 监听所有网卡
  port: 5173,
  proxy: { '/api': { target: 'http://127.0.0.1:8000' } }
}
```
注意：proxy.target 仍写 `127.0.0.1`（前端进程内部连本机后端）。

**2. 启动后端绑 0.0.0.0**
```powershell
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

**3. 找本机 IP**
```powershell
ipconfig | findstr IPv4
# 例如 192.168.1.100
```

**4. 局域网设备访问**
- 浏览器：`http://192.168.1.100:5173`
- 教师机防火墙要放行 5173 端口（见 §5.3）

### 5.3 Windows 防火墙

```powershell
# 管理员 PowerShell：放行 5173
New-NetFirewallRule -DisplayName "ClassPet Frontend" -Direction Inbound -LocalPort 5173 -Protocol TCP -Action Allow
# 同时放行后端 8000（如果后端也要直连，比如 swagger ui）
New-NetFirewallRule -DisplayName "ClassPet Backend" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
```

## 6. 数据库管理

### 6.1 数据库文件位置

```
class-pet-backend/class_pet.db
```

这就是全部业务数据。**复制走它就是完整备份**。

### 6.2 备份

仓库内置了备份脚本（保留 30 天，自动清理超期）：

**Windows**：
```powershell
.\tools\backup.ps1
```

**macOS / Linux**：
```bash
chmod +x tools/backup.sh
./tools/backup.sh
```

备份文件存到 `backups/class_pet_<时间戳>.db`，可直接复制到 U 盘 / OneDrive 异地保存。

#### 设置每日自动备份

**Windows 任务计划程序**（管理员 PowerShell 一次执行）：
```powershell
$root = "E:\2026_CLAUDE_CODE_MAX\teacher_app"
$action = New-ScheduledTaskAction -Execute "powershell.exe" `
    -Argument "-NoProfile -ExecutionPolicy Bypass -File `"$root\tools\backup.ps1`""
$trigger = New-ScheduledTaskTrigger -Daily -At 2:00am
Register-ScheduledTask -TaskName "ClassPetBackup" -Action $action -Trigger $trigger
```

**Linux / Mac crontab**：
```bash
crontab -e
# 加一行：每天凌晨 2 点
0 2 * * * /path/to/teacher-app/tools/backup.sh >> /tmp/class-pet-backup.log 2>&1
```

#### 恢复备份

```powershell
# 1. 停服务
# 2. 用备份覆盖
Copy-Item backups\class_pet_20260503_0200.db class-pet-backend\class_pet.db -Force
# 3. 启动服务
```

### 6.4 迁移到 MySQL（含数据搬迁）

**适用场景**：
- 多老师并发使用 / 数据量增长 / 部署到云服务器
- 想绕开 SQLite + Windows 下 alembic 不 commit 的坑

**完整步骤**：

```powershell
# === 准备 ===

# 1. 安装 MySQL 8 + 启动服务（去 https://dev.mysql.com/downloads/installer/ 下载）

# 2. 建数据库 + 用户
mysql -u root -p
mysql> CREATE DATABASE teacher_app DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;
mysql> CREATE USER 'classpet'@'localhost' IDENTIFIED BY 'your_strong_password';
mysql> GRANT ALL ON teacher_app.* TO 'classpet'@'localhost';
mysql> FLUSH PRIVILEGES;
mysql> EXIT;

# 3. 备份现有 SQLite（重要！迁移失败可回滚）
.\tools\backup.ps1

# === 迁移 ===

cd class-pet-backend
.\.venv\Scripts\Activate.ps1

# 4. 改 .env：注释 SQLite 行，加 MySQL 行
notepad .env
# DATABASE_URL=mysql+pymysql://classpet:your_strong_password@127.0.0.1:3306/teacher_app?charset=utf8mb4

# 5. 让 MySQL 建好所有表（含 seed）
python init_db.py

# 6. 把 SQLite 现有数据搬过去
python migrate_sqlite_to_mysql.py

# === 验证 ===

# 7. 启动服务，登录原账号验证
uvicorn app.main:app --reload
# 浏览器访问 http://127.0.0.1:5173 ，所有班级、学生、宠物、行为应该都在
```

`migrate_sqlite_to_mysql.py` 行为：
- 校验 `.env` 已切到 MySQL，否则拒绝执行
- 按外键依赖顺序逐表搬迁（共 15 张业务表 + alembic_version）
- 对每个表先 DELETE 再 INSERT，**保留原始 ID**（外键关系不变）
- AUTO_INCREMENT 重置到 max(id)+1
- 任一步失败整体事务回滚
- 大概 1-2 秒（取决于 behaviors 表大小）

**回滚**（万一出问题）：把 `.env` 改回 SQLite 即可，原 `class_pet.db` 没动过。

## 8. 故障排查

### 8.1 后端启动报「端口已被使用」

```
ERROR: [Errno 10048] error while attempting to bind on address ('127.0.0.1', 8000): ...
```

**原因**：8000 端口已经有进程在用。

**解决**：
```powershell
# 找出 PID
netstat -ano | findstr ":8000.*LISTENING"
# 假如显示 PID 是 12345
taskkill /F /PID 12345

# 或者用 PowerShell（更稳）
Get-NetTCPConnection -LocalPort 8000 -State Listen |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

如果遇到「PID 找不到但端口仍 LISTENING」的僵尸状态（Windows 偶发），换端口启动：
```powershell
uvicorn app.main:app --reload --host 127.0.0.1 --port 8001
# 注意改 vite.config.ts 里 proxy.target 也改成 8001
```

### 8.2 后端启动报「bcrypt」相关错误

```
AttributeError: module 'bcrypt' has no attribute '__about__'
```

**原因**：bcrypt 5.x 跟 passlib 1.7.4 不兼容。

**解决**：
```powershell
pip install "bcrypt<5"
```

`requirements.txt` 已经写了 `bcrypt<5`，正常 `pip install -r requirements.txt` 不会装到 5.x，但如果误升级了执行上面。

### 8.3 前端报「Cannot find module xxx」

**原因**：node_modules 没装好或损坏。

**解决**：
```powershell
cd class-pet-frontend
Remove-Item -Recurse -Force node_modules, package-lock.json
npm install
```

### 8.4 关键坑：alembic 迁移在 SQLite/Windows 不真正 commit

**症状**：`alembic upgrade head` 输出"Running upgrade ..."无报错，但数据库里表/列没真正创建，`alembic_version` 也是空。

**自检**：
```powershell
python -c "import sqlite3; con=sqlite3.connect('class_pet.db'); print('tables:', sorted(r[0] for r in con.execute(\"SELECT name FROM sqlite_master WHERE type='table'\"))); print('version:', list(con.execute('SELECT * FROM alembic_version')))"
```

正常应看到 13 张表 + 一个 alembic_version 值。

**应对**：
1. 确认 Python 进程不在持有 db（停掉所有 uvicorn）
2. 直接用 sqlite3 命令手动跑 SQL
3. 手动 stamp version 号：
```python
import sqlite3
con = sqlite3.connect('class_pet.db')
# 最新 head 在 alembic/versions 看，例如：
con.execute("UPDATE alembic_version SET version_num='2f91651af525'")
con.commit()
```

**根因未深究**，疑似 alembic env.py 里 `with context.begin_transaction()` 在 SQLite "non-transactional DDL" 模式下没正确 commit。**MySQL 不会有这个问题**——这是切 MySQL 的一个动力。

### 8.5 浏览器 401 / 跳登录

**原因**：JWT 过期（默认 7 天），或后端重启了 `JWT_SECRET` 变了导致老 token 失效。

**解决**：重新登录即可。如果想避免重启后失效，把 `.env` 里的 `JWT_SECRET` 固定（不要每次部署随机生成）。

### 8.6 局域网其他设备访问不到

按 §5.2 检查清单：
1. 前端绑 `0.0.0.0` 了吗？
2. 后端绑 `0.0.0.0` 了吗？
3. 防火墙 5173 / 8000 端口放行了吗？
4. 教师机和学生机在同一网段？（用 `ping 教师机IP` 验证）

### 8.7 日期变化后宠物属性没衰减

**不是 bug**：衰减是「懒计算」——读取宠物时才算。如果想立即触发，在前端学生详情页刷新一次即可。

## 11. 紧急救援清单

服务挂了排查顺序：

1. 浏览器 F12 → Network 看请求是哪步失败
2. 后端 cmd 窗口看有没有红色 ERROR
3. `curl http://127.0.0.1:8000/api/v1/ping` 直接打后端，确认后端活着
4. `curl http://127.0.0.1:5173/api/v1/ping` 走前端代理，确认 vite 代理工作
5. 都不通 → 杀进程重启（§7.2）
6. 重启还不行 → 看后端启动报什么错（§8.1-8.3 对号入座）
7. 数据丢了 → 从最近一次备份恢复（§6.2）
8. 全炸了 → 删 db 重建（§6.3）—— 但**会丢数据**
