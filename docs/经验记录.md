## 2. ✅ 值得复用的 6 条模式

### 2.1 数据驱动 优先于 代码硬编码
**反例**：第一版宠物场景按房子名 if/else 切 CSS 主题（"城堡"紫色、"木屋"棕色）。用户立即纠正"不能写死"。

**正例**：重做后直接渲染 `shop_item.icon` emoji 大图，新增任何房子只要 seed emoji 就自动显示，不改一行代码。

**判断标准**：如果某段代码出现"几种情况枚举"的 if/else，先问一句"这个枚举该不该进数据库？"

### 2.2 渐进增强：图片优先 emoji 兜底
`PetAvatar` 组件统一封装：有 `image_url` 显示图，没有显示 emoji，加载失败也降级 emoji。**新功能上线不破坏老用户视觉**，是这种产品最重要的事。

### 2.3 子 agent 做验收
关键迭代后用 `general-purpose` agent 跑一遍 review，找出主 agent 自己漏的 bug。这次找出 4 个必修：
- Dashboard 等级榜跳错学生（pet_id ≠ student_id）
- utcnow 时区漂移 8 小时
- 撤回 toast 没刷新父组件
- 前端时间普遍偏移 8 小时

**性价比最高的工程实践**。下次复杂迭代后必做一次。

### 2.4 业务规则可视化
成绩趋势 SVG 折线 + A/B/C/D 4 段彩色背景区，一眼看出"卡在 B 层"还是"稳 A"。比纯数字表格直观 10 倍。这种"把规则画在背景里"的思路可以推广到 班级积分分布 / 行为热力图 等场景。

### 2.5 事务 + flush 而非 commit
批量打分逐个学生应用，用 `db.flush()` 拿 ID，最后一次 `db.commit()`。任一失败整体回滚，不会出现"3 个学生加分了，第 4 个失败了"的脏状态。

### 2.6 操作即时反馈 ≠ 必须确认按钮
失焦自动保存（作业批改）+ 撤销 toast（5 秒可撤回）的组合 比"输入 → 点保存按钮"快得多，又不会误操作。**对高频操作场景非常值**。

## 3. ❌ 踩过的坑（下次警惕）

### 3.1 alembic + SQLite + Windows 不真正 commit
每次新增 migration，`alembic upgrade head` 会输出"成功"但 db 中实际没建表 / 没写入 alembic_version。

**应对**：每次新增迁移后，**强制用 sqlite3 直连验证**：
```python
import sqlite3
con = sqlite3.connect('class_pet.db')
print([r[0] for r in con.execute("SELECT name FROM sqlite_master WHERE type='table'")])
print(list(con.execute('SELECT * FROM alembic_version')))
```
缺表就手动 ALTER + UPDATE alembic_version。考虑写成 `tools/verify_migrate.py`。

### 3.2 端口被外部项目占用而无察觉
8000 被另一个 python 项目占了，前端 vite 代理打到错的服务，"页面没数据"两小时后才查到。

**应对**：
- vite.config.ts 已经支持 `.env.local` 配端口
- 前端有 `BackendHealthBanner` 启动时 ping 一次后端，连不上明显告警
- 启动后跑一句 `curl http://127.0.0.1:5173/api/v1/ping` 确认走代理拿到我们的服务

### 3.3 时区从一开始就要做对
`datetime.utcnow()` 是 naive UTC，序列化没 `Z` 后缀，浏览器 `new Date()` 按本地解析 → 偏 8 小时。

**应对**：
- 后端写时间用 `datetime.now(timezone.utc)`（aware）
- 序列化输出含 `+00:00` 或 `Z`
- 前端用统一的 `parseBackendTime()` 工具，遇到 naive 字符串补 `Z` 兜底

### 3.4 跨组件事件链断开就会有"为什么没刷新"的 bug
撤销 toast 调用 `DELETE /behaviors/{id}` 后，BehaviorQuickPanel 的 onUndo 写成空注释，导致父组件 StudentDetailView 不刷新。验收子 agent 找出来才修。

**应对**：每加一条新的事件路径，画一遍：
```
组件 A 触发 → 组件 B 回调 → 组件 C 收到事件 → 重拉数据
```
每个箭头都要写代码连接。defineEmits 留空 / 空注释 / `// TODO` 都要立即 grep 自查。

### 3.5 复杂 Vue template 嵌套容易写错闭合
`<el-dropdown>` 套 `<template #dropdown>` 套 `<el-dropdown-menu>` 时把 `</template>` 写成 `</el-dropdown>`，Vue 编译器报错指向无关的行号，难定位。

**应对**：模板嵌套层级超过 4 层 → 拆成子组件。或者写完立即看 Vite 编译输出。

### 3.6 UX 二段式流程对新用户极不友好
图片上传"先保存等级再回来上传图片"的设计，用户直接说"上传失败"——其实是按钮被隐藏了他没看见。

**应对**：每个交互做完，扮演新用户从零走一遍。如果某步必须依赖前一步的产物（"先保存再 X"），改成单步内自动衔接（这次改成"上传时如果还没创建则自动先创建再上传"）。

### 3.7 uvicorn 热重载偶发失效
新增 `app/api/v1/<name>.py` 后 `__init__.py` 注册，uvicorn 不一定能热更，路由不出现。

**应对**：改了路由聚合或新增 model 后**主动重启**，不依赖热重载。

### 3.8 写"先 API 再 UI"避免反复改
某次先做 UI 弹窗、后端再写时发现字段对不上要返工。**先把 API schema 想清楚 + 后端实现 + curl 测**，再做前端，节省至少一半时间。

## 5. 各功能"性价比"事后评分（用户感知度 × 实施成本）

| 功能 | 实施时长 | 用户体感 | 评分 |
|---|---|---|---|
| 验收子 agent | 0.2h | 高（找出 4 个真 bug） | ⭐⭐⭐⭐⭐ |

| 撤销 toast | 0.5h | 中高（防误操作） | ⭐⭐⭐⭐ |
| Dashboard | 1h | 中（首屏存在感强） | ⭐⭐⭐⭐ |

## 6. 最后一条：节奏

每轮做 1-2 个聚焦的功能 → 验证 → 简短回报 → 用户决定下一轮。**不要一次铺开 5 个功能**，那样回滚成本高、用户也跟不上。

每轮报告控制在 200 字以内：做了什么 / 验证通过 / 下一轮候选。
